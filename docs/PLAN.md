# Grim Fandango: PointyClicky Edition — the plan

*The afterlife. Finally on point.* (Simon, 14 Nov 2026)

**The mission.** Grim Fandango, start to credits, by pointing and clicking, so
that it feels as if LucasArts released it this way in 1998.

**The method.** No guesswork and no "add it when someone trips over it".
The game's own files already say everything a pointer needs to know: what
exists, where it is, what it does and when it's live. We read that first,
build on it, and prove the result against it.

---

## The laws (true everywhere, no exceptions)

1. **The game is the source of truth.** Every thing you can point at is an
   object the game's own scripts create, at the position they give it,
   while the game says it's touchable. Nothing is invented, and nothing the
   game offers is missing.
2. **Every input is one of the game's own actions.** A click only ever calls
   what the original keyboard player could do: the object's own `use`,
   `lookAt`, `pickUp`, `walkOut`, the game's inventory, the game's dialogue
   choice, the game's own pathfinding. The edition adds a way to *reach*
   those actions, never new behaviour. So every line Manny says and every
   puzzle result stays the original.
3. **Live, not frozen.** At runtime the list of things under the pointer
   comes from the game's state as it is now (`make_touchable`, objects moved
   by scripts, actors walking). Hand-drawn data only adds the *shape* of a
   thing on screen, never whether it exists.
4. **One gesture, one meaning, everywhere.** It's the same as every other
   PointyClicky game: the game's pointer, tap = the main action, two-finger
   tap = look. No mode, scene or special puzzle changes what a gesture means
   without the screen showing it.
5. **The original look.** Software renderer, 640×480, hard pixels (Simon,
   11 Nov 2026). The edition's own pieces (cursor, highlights) are drawn
   for that screen, in the game's art deco, and never look like an overlay.
6. **Proven, not assumed.** "Done" means a machine-checked audit at zero and
   a pointer-only playthrough from a new game to the credits, plus Simon's
   sign-off on the phone.
7. **Ours, in the open.** GPL-2.0+, Grim Mouse credited. The repo never
   contains the game's files: tools read the player's own copy.

## The answer key (phase 0: from the game itself)

One table, generated by `tools/inventory.py` from the player's own copy,
that every later phase is checked against:

| Fact | From | Status |
|---|---|---|
| Every object: id, name, 3D position, reach (`range`) | `Object:create` in each set's Lua | done: 680 placed, 129 sets |
| What each object does | its handlers (`lookAt`, `use`, `pickUp`, `walkOut`, `use_<item>`) | done |
| When it's live | every `make_touchable` / `make_untouchable` in the scripts | done (the flags); the conditions next |
| Every camera angle, and which you play in | set files: setups + camera sectors | done: 141 play angles |
| Where each object lands on each angle | the engine's own projection | done |
| Whether it's hidden there | the angle's depth image (`.zbm`) | next |
| Every exit | walk sectors, door objects' `walkOut`, the set-change scripts | next |
| Every moment the game takes the controls | scripts installing their own button handler | found: 29 installs, 24 moments (docs/moments.md) |
| Every conversation | the dialogue scripts (`dlg_*`) | found: 39 scripts |
| Every item | the inventory scripts and the item renders | next |

**Output:** `build/inventory/` (machine) and a contact sheet per play angle:
the real background, the game's point for every object, our outline over
it, and every exit. That's the one picture where a gap can't hide.

## Phase 1: the decisions (Simon, 14 Nov 2026)

1. **The verbs: closest to the original.** The original has three: Use (U),
   Pick up (P, also puts an item back in the coat) and Examine (E). The
   answer key says how often they really differ. Of the objects with both
   Use and Pick up, 114 run the same code for both, and on 112 more Pick up
   is only a remark ("I don't need that"). On 4, Use is only a remark and
   Pick up acts. Only **38** run genuinely different code for the two.
   - Tap = the object's action: its `use`, or its `pickUp` where `use` is
     only a remark. On a door, `walkOut`. With an item in hand, `use` with
     that item, as the original's U does.
   - Two-finger tap = Examine (`lookAt`).
   - **Manny is the coat:** tap Manny to open his inventory, as reaching for
     I did. With an item in hand, tap Manny to put it back (the original's P).
   - **No verb menu** (Simon, 14 Nov 2026, over the Remaster's "verb skull",
     a Look/Use/Pick up pop-up on every click): one tap, one meaning, no
     menu over the scene, ever.
   - **The 38**: each is checked in the game's scripts and in the playthrough.
     Where Pick up is needed to finish or is a line worth hearing, it gets a
     reachable form. The list is the answer key's, not a guess.
2. **The cursor: settled (Simon, 14 Nov 2026, on his phone: "pixel size looks
   about right").** His bone crosshair, 26 px, no centre dot, in Manny's own
   bone colours (m_bone/m_jaw through suit.cmp), drawn by `tools/cursors.py`:
   bone at rest, marigold over something Manny has noticed, nothing in
   cut-scenes. (Earlier: follow the Remaster's theme, drawn our own way (none of
   Double Fine's art). The Remaster's family (looked at 14 Nov 2026): a
   thin crosshair at rest, a starburst over a thing, a ring of dots while
   the game is busy, four block arrows for exits (each hotspot names its
   direction), and a dimmed crosshair when nothing can be done. Flat:
   white outline on black. Ours keeps those roles and that restraint, drawn
   in pixels for 640x480.)
3. **The inventory: Manny's coat, 100%.** The original's own one-at-a-time
   reveal, driven by the pointer.
4. **Running: double tap.**
5. **Discovery is Manny's head, as in 1998. No text labels, ever** (Simon,
   14 Nov 2026, after the proof of concept: "that's how the game was
   designed and it had charm"). **Manny finds, the cursor confirms** (Simon,
   14 Nov 2026, over "the cursor finds", which steals the head's job):
   - Manny's head does what it did in 1998 and only that: he glances at things
     as he passes, by the game's own rule. It never follows the pointer.
   - The cursor goes marigold only over a thing Manny has noticed (his head has
     turned to it). Unnoticed things stay bone, though a tap on them still acts.
   - "Noticed" is the game's own head-look target, read live, never a list of
     ours. The 1998 rule, in `_system.lua`: every frame `Find_Visible_Objects`
     builds `vlist` (visible, touchable, within the object's own `range` of
     Manny), and `Head_Control` picks `hot_object` from it (nearest in angle,
     taking turns between near-equal ones), which `head_look_at` turns his
     head to. An object is **noticed** once it has been `hot_object`, and it
     stays noticed **for good in that playthrough** (Simon, 14 Nov 2026): amber
     on every later visit, kept in the save (Continue remembers). Things the
     story switches on later are new, so they need noticing in their turn.
     A tap on an unnoticed thing still acts: amber only confirms.

6. **Old saves: not needed.** No one has played Grim in the app yet, so the
   edition is the only way Grim has ever played in PointyClicky.

## Proof of concept (Simon, 14 Nov 2026, on his phone)

Grim Mouse's port with a first cut of our cursors, on the software renderer:
**"this is 100% the way to play."** How it works is right. What isn't: the
look of the cursors and icons, and the text (Grim Mouse's hover names in the
emergency font). Those are ours to design (phase 2 and the decisions above).

## Phase 2: the engine (built once, true for every scene)

- **The live list.** Each frame, the candidates under the pointer are the
  current set's objects the game marks touchable, at their current
  positions, plus actors you can talk to. That's law 3, and it ends
  "missing" and "stale" for good.
- **Shapes.** An object's outline per angle comes from our data. Where we
  have none yet, the engine falls back to the object's projected point and
  reach, so nothing is ever unclickable. The audit counts every fallback
  so it shows up as work left.
- **Characters, live (15 Nov 2026).** An object that stands for a character
  (the game's `X_obj` for its actor `X`, plus the five the scripts tie to
  another name: terry, zod, chepito, maximino, gate_keeper) is linked to its
  actor by mouse.lua (`LinkHotspotActor`, on every hotspot refresh and after
  a load), and the engine finds it where the character is drawn this frame
  (the costume's box on screen, as the engine measures it to place speech),
  not on a fixed outline. Where an object nearer the camera is under the
  pointer too, the object wins (a desk in front of the clerk). When the
  character isn't drawn, the outline is used as before. Proven on the bench:
  a click on Eva's legs, outside her old outline, starts her conversation
  (build/bench/j3-*).
- **Exits** come from the sectors and door objects (the answer key), not
  from hand-placed "to" polygons.
- **Every action through the game.** Walking uses the game's own pathing.
  Use, look and pick up call the object's handlers, exactly as the keys did.
- **The app drops tank controls**: the joystick, the steering switch and
  Grim's own gesture set go. Grim plays through the trackpad like the rest.

- **Saves carry the scripts** (found 14 Nov 2026): Grim saves its whole Lua
  state, functions included, so a save made before a fix to the edition's
  scripts brings the old ones back. On every load the engine must run the
  edition's script again (mouse.lua, written so a second run is harmless), so
  an update reaches saves made before it.
  **Done (15 Nov 2026):** the engine runs mouse.lua again after every load;
  its objects are created only if missing, its renames only if the name
  differs, wrapped functions captured once. The outlines too: after a load
  they come from the data again (a hotspot a script moved keeps its place).
  Proven on the bench: a save made with the pre-coat mouse.lua opens the coat
  after the load (build/bench/j1-*).

## Phase 3: the data (every scene, measured)

- Outlines for every object on every play angle. Each is seeded from the
  depth image (an object's silhouette is a jump in depth), then reviewed on
  the contact sheet. Grim Mouse's outlines are kept where the audit agrees
  with them.
- **Target: the audit at zero.** No missing object, nothing off, no stray,
  no fallback, every exit marked. Anything left gets a written reason (a
  thing the game creates but never shows, say).

## Phase 4: the 29 moments the game takes the controls

Each is a scene whose script installs its own key handler: the forklift,
the elevators, the Bone Wagon, the computer, the roulette panel, the
climbs, the linear puzzles and so on (29 handler installs, 24 moments: each
one proposed in docs/moments.md, for Simon to approve before any is built). Each one
gets a designed pointer version that sends that handler the same keys the
original's player pressed (law 2), with the same rule set for all of them:
point where you want to go or what you want to work, and click.

## Phase 5: proof

1. **Static**: `inventory.py` at zero (phase 3).
2. **Pointer-only playthrough**: the walkthrough machinery plays the whole
   game from a new game to the credits, every action by moving the pointer
   and clicking (no keys). It needs a Grim state reader, which also gives
   Grim a walkthrough and NudgeAI hints.
   **In progress (docs/proof.md):** played by pointer from a new game, Year 1
   through El Marrow and the Petrified Forest: the tree pump, the sign and the
   key from the cave so far (15 Nov 2026); sixteen fixes on the way (two dead
   ends: Copal's computer kept the pointer after it closed; the wheelbarrow's
   pull never ended), one question for Simon.
3. **Coverage**: during that run, every object the game ever made touchable
   was reachable by the pointer at least once.
4. **Known faults**: Grim Mouse's crash at Domino's computer (#48), its
   inventory close slip, the `vd.lua` merge, all fixed and covered by the run.
   **#48 fixed (15 Nov 2026).** The computer is Copal's (co, Year 1: the
   auto-reply), not Domino's. Cause: a hover queues `draw_choices`, the click's
   `make_selection` runs ahead of it, and when the reply doesn't change
   `stop_interface` purges the screen's primitives in that same frame, so the
   queued `draw_choices` hits a purged one (`ChangePrimitive` asserts).
   Reproduced on the bench (second visit, same reply: the assertion); fixed in
   mouse.lua (`draw_choices` and the pointer do nothing once
   `interface_active` is off); after it, no crash, and saving and loading
   inside the computer and choosing reply 5 work (build/bench/j2-*). The
   "corrupt save" in the report was stock ResidualVM 0.2.0 failing to load a
   Grim Mouse save (no Grim Mouse opcodes there: `obj->value.f`), not damage.
5. **Simon on the phone**: a scene-by-scene sign-off sheet, Year 1 to Year 4.

## Phase 6: release

- In PointyClicky: Grim plays the edition, with its walkthrough and hints.
- The repo goes public with a README, the plan, the answer key's tools,
  credits and a changelog.
